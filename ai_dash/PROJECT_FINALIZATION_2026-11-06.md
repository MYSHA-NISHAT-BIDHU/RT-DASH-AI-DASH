## Final repair made in this pass

The independent C++17 test executable previously relied on the standard C/C++ `assert(...)` macro. A Release build normally defines `NDEBUG`, which can remove those checks and also remove expressions with side effects contained inside an assertion. This made a successful Release-mode `ctest` weaker than it appeared.

`research_cpp/tests/test_scheduler.cpp` now uses an explicit `require(...)` function that throws on failure. The checks therefore execute in Debug and Release builds alike, including resource-reservation/release operations that were previously embedded in assertions.

This is a test-harness reliability correction only. It does not change the scheduler, predictor, experiment configuration or archived numerical results.

## Current manuscript-aligned evidence boundary

The project supports a software-simulation claim only. CPU, memory, storage and bandwidth forecasting targets are synthetic preprocessing annotations. The project does not establish physical-board WCET, measured RTOS overhead, MCU inference latency, physical energy consumption, hard-real-time certification or external-site generalization.

The principal AI-DASH result is not "AI always beats deterministic semantic detection." Under the current primary matrix, predictive-and-load entry reduces mean high-criticality DMR from 0.032169 for load-only RT-DASH to 0.000000, but direct semantic RT-DASH also reaches 0.000000 and has the shorter mean high-criticality response. The safe predictive recovery-aware policy matches deterministic recovery-aware RT-DASH on the principal nominal aggregate metrics. These negative/equal results are intentionally retained.
