# Frozen ARIMA + LSTM Thesis-Completion Protocol — 6 August 2026

## Purpose

This additive simulation-only study implements the predictive mechanism stated
in the MSc thesis without restoring the leakage in the thesis-era script. It
does not replace or retune the already locked deterministic RT-DASH or
sensor-state AI results.

## Source and evidence boundary

Input is the fixed thesis-era processed OpenSHS table
`../data/processed/processed_smart_home_dataset_with_resources.csv`.
`CPU`, `Memory`, `Storage`, and `Bandwidth` are **synthetic simulation
annotations generated by the thesis preprocessing script**. Forecast accuracy
therefore demonstrates correct forecasting/integration of the thesis simulation
resources; it is not a claim of measured physical resource prediction.

Source-quality rule fixed before model fitting: the single row with missing
values in all four resource columns is dropped rather than interpolated. Missing
`Activity` values (introduced by the thesis preprocessor's omitted `leisure`
mapping) are mapped to the non-critical `other` class for scheduler integration;
they are never used as resource-forecast targets or features.

## Chronology

- resampling: non-empty 60-second bins;
- train: first 8 source dates;
- validation: next 3 source dates;
- test: final 3 source dates;
- forecast horizon: one 60-second step;
- LSTM look-back: 12 preceding bins (12 minutes);
- windows never cross a discontinuity in the resampled timestamp sequence;
- scaling statistics are fitted on train only;
- test is never used for model fitting, early stopping, threshold selection, or
  architectural choice in this study.

The final three dates were previously used by the separate sensor-state AI
study, so this new branch must be described as a **thesis-completion study**, not
as a newly collected external test site.

## Models fixed before forecasting-test execution

1. persistence baseline: previous observed resource value;
2. ARIMA(5,1,0): conditional least-squares AR(5) model on first differences,
   fitted separately for CPU, Memory, Storage, and Bandwidth;
3. LSTM: one-layer multivariate LSTM, 4 inputs, 16 hidden units, 4 linear
   outputs, trained with Adam on standardized resources;
4. thesis hybrid: ARIMA CPU forecast + LSTM Memory/Storage/Bandwidth forecasts.

LSTM training contract: seed `20260806`, learning rate `0.005`, batch size 128,
maximum 40 epochs, gradient clip 5, validation-only early stopping with patience
6. No test metric may select an epoch or parameter.

## Forecast metrics

Report MAE, RMSE, sMAPE, R² and RMSE divided by the train-set standard deviation
for every resource/model/split. Negative or inferior results are retained.

## Combined predictive pressure

Each hybrid resource forecast is converted to its percentile in the *training*
resource distribution. The combined score is

`0.4*CPU + 0.2*Memory + 0.2*Storage + 0.2*Bandwidth percentile`.

This score is an advisory prediction in `[0,1]`; it is not a calibrated
probability.

## Scheduler integration

- forecast blocks: 120 eligible minute bins, with fragments of at least 30;
- simulator step between trace events: 100 ms;
- quantum: 10 ms;
- background utilization targets: 0.30, 0.45, 0.60;
- scheduler threshold: selected only on validation blocks using the same
  safety-dominant objective as the existing predictive integration;
- test systems: EDF, load-only RT-DASH, semantic RT-DASH, recovery-aware
  RT-DASH, ARIMA+LSTM predictive-only, safe hybrid, and safe recovery-aware
  hybrid.

The safe policies retain deterministic semantic and utilization guards. The
forecast may enter Critical Mode earlier, but it cannot disable a deterministic
guard.

## Prohibited claims

No physical hardware, energy, MCU inference time, WCET, measured resource
demand, universal schedulability, causal prediction, or broad external
generalization claim may be made from this branch.
